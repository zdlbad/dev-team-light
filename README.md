# dev-team-lite

一个轻量的模型驱动开发团队：六个角色，各自只写三样——会做的事、做事的原则、输出的形状。指挥把角色一步一步派出去，你在页面上答问题、按「定下」。

## 角色

| 角色 | 管什么 | 文件 |
|---|---|---|
| 指挥 | 提议下一个任务、派活、收活、记现场、给你看页面 | [roles/指挥.md](roles/指挥.md) |
| 项目管理 | 需求清单、日程、里程碑 | [roles/项目管理.md](roles/项目管理.md) |
| 业务 | 全局图、概念图、流程、上下文地图 | [roles/业务.md](roles/业务.md) |
| UI 设计 | 项目界面的小样：一条需求开工前照它模拟操作，细化、确定、发现需求 | [roles/UI 设计.md](roles/UI%20设计.md) |
| 建模 | 聚合、调动清单与流程 | [roles/建模.md](roles/建模.md) |
| 软件工程师 | 规范、技术选型、文件结构、伪代码、代码 | [roles/软件工程师.md](roles/软件工程师.md) |

## 一个项目长什么样

```
<项目>/
  项目.json                         上下文有哪些、共享内核里有什么（业务画上下文地图时写）
  上下文图.json                     上下文之间的事件与查询（业务写）
  项目管理/需求.json  日程.json
  共享内核/业务/概念.json
  上下文/<名>/业务/   全局图.json  概念/<主题>.json  流程/<流程名>.json
  上下文/<名>/界面/   <需求编号>.json  <需求编号>/<屏 id>.html      UI 设计写，一条需求一份，里面按视角分屏
  上下文/<名>/模型/<主题>/   聚合/<聚合名>.json  调动/清单.json  调动/<流程名>.json
  上下文/<名>/代码/   规范/{结构设计,文件命名,技术选型}.json  结构.json  伪代码/<文件路径>.json  src/
  现场.json  派工/<日期>-<序号>.json  日志/<日期>.jsonl
```

项目下面一层是上下文（比如 养老系统、聊天 app、排版系统），各有自己的业务、模型、代码；共用的概念写进共享内核；上下文之间只靠事件和查询来往。

## 思路

先搞懂业务，才能说明白、听明白功能和需求。所以顺序上是：业务先画全局图、概念图、流程图 → 项目管理定需求 → UI 设计照需求出小样，小样用来细化需求、确定需求、发现需求 → 建模 → 编码。这个顺序不写死，是个思路。

## 怎么走

1. 项目管理收需求、定取舍、排日程；每个任务三个阶段 业务 → 建模 → 编码
2. 一条需求开工前，UI 设计照它出小样：需求是系统功能，碰到几个角色就分几个视角，每个视角各自一串屏。你在「界面」页按一遍：一屏说清了就定下这一屏，没说清的改小样、冒出来的记需求候选
3. 指挥按日程提一个任务，你说做
4. 指挥派角色做任务当前的阶段；角色交回，指挥先把画出来的图截图看一遍（`node tools/shot.js`），遮挡重叠的调好；有问你就答，没问你去那一页按「定下」。业务的规则一条条挂在流程里触发它的那一步上，没定的规则和业务的问题也留在那一步，你在业务页答，左边栏红点告诉你还有几条；「谁在干什么」只提醒一句
5. 定下＝这个阶段完成，日程里填上日期，指挥派下一个阶段
6. 三个阶段都定了，任务完成，回到 2

## 工作台

```
node workbench.js <项目目录> [<项目目录>…] [--port 4870] [--now "2026-11-09 16:20"]
```

一个地址，可以开好几个项目，每个项目六页：谁在干什么、项目管理、业务、界面、建模、编码（地址 `/<项目目录名>/<页>`，首页跳到第一个项目的「谁在干什么」）。项目管理页左边栏最上面的「总览」把开着的项目一页列全：每个项目几期、每期的目标和进度，项目名点过去就换项目。页面就是 `_wip/` 里的小样，数据从项目目录读出来注进去（`lib/project.js` 管读与写）；页上按「定下」「答」写回那个项目的 项目管理/日程.json、上下文/…/界面、现场.json 和 日志/。`--now` 把「现在」钉在某个时刻，对着样板项目看页面用。

`_wip/样板项目/` 是各份小样的写死数据按上面的布局落成的项目，`node tools/export-fixture.js` 重新生成；工作台先对着它跑。

`templates/` 是软件工程师定规范时拿来的默认，三类各一份，形状和上下文里存的一样；`_wip/` 是定角色时做的小样页面，每份带一个 `check.js` 能跑。
